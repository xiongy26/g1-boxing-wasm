# G1 真人拳击效果优化方案

> 编写日期：2026-09-26。
> 本文基于当前代码、已部署策略及本次回归结果，描述后续修改计划；不代表这些修改已经实现。
> 目标环境仍为 MuJoCo WASM + Three.js 浏览器仿真，训练在离线环境完成。

## 1. 目标与范围

让两台 G1 能保持拳击架势，围绕对手移动，并完成自然的“试探—进攻—防守—反击—恢复距离”。第一步只做守卫、刺拳及简单攻防交换，验收通过后再扩展拳法和自由对练。

“真人拳击感”拆成四项可检查的能力：

1. **动作形态**：拳套护头、收肘、前后脚站位，以及腿、腰、手臂协调的出拳和收拳。
2. **空间关系**：持续面向对手，主动保持适合自身臂展与拳法的距离，能够进退和绕行。
3. **交互反应**：出拳指向实际目标，防守响应来拳，受击后有合理的身体恢复。
4. **连续性与稳定性**：动作连接自然，减少站桩等待、滑脚、缠倒和依赖回合重置的情况。

G1 的身体比例、关节范围和力矩能力与人类不同。动作需适配机器人动力学，以可执行的拳击动作和攻防节奏为目标，不要求逐关节复制人体。

## 2. 当前基线与主要问题

| 项目 | 当前证据 | 对效果的影响 |
|---|---|---|
| 默认 AMO 模式 | 全身策略负责平衡运动，手臂目标由预设姿态驱动；本次 22 秒无头回归通过 | 已有完整对战闭环，但拳法表达受预设目标与节奏限制 |
| 守卫数据 | `cut_boxing_clips.py` 使用通用站姿，并合成周期弹跳 | 缺少专门设计和验证的拳击架势 |
| 动作节奏 | 出拳片段两端各有 1 秒保持与 0.5 秒过渡，共约 3 秒附加时长 | 短拳被拉成长片段，等待明显，连击困难 |
| 追踪步法 | 接近、后退、侧移都映射到 `guard` | 战术指令没有对应的位移能力 |
| 对手感知 | 追踪运动层主要观测自身与参考动作；初始参考朝向按双方固定设置 | 难以随对手位置调整出拳与朝向 |
| 动作调度 | 主要等片段结束后切换 | 反应滞后，不能自然衔接收拳、连击和防守 |
| 部署拳法 | 本次检查中 `boxing_hook.bin` 与 `boxing_jab.bin` 的 SHA-256 相同 | 四个槽位不等于四套独立拳法权重 |
| 平衡辅助 | 浏览器默认开启；追踪模式包含托力、扶正力矩、水平阻尼及贴身分离力 | 展示稳定性不能直接代表策略自身能力 |
| 命中规则 | 接触加冷却计分，命中后沿预设方向额外施加击退力 | 轻触、贴身挤压和有效出拳区分不足 |

本次验证结果：

- `node tools/test_amo.mjs 22`：通过，覆盖出拳、命中、注入伤害后的 KO 与回合恢复。
- 四个 `boxing_*` 槽位的 `test_tracking.mjs`：全部通过保存的 ONNX 参考向量对齐检查。此结果仅验证推理一致性，不验证动作质量。
- `node tools/test_tracking_boxing.mjs 22 boxing`：本次失败，关闭辅助后在出拳阶段出现摔倒。测试含随机决策，单次结果不能作为失败率统计。

现有 README 和阶段记录部分内容早于代码。后续每次策略部署应记录实际权重版本、运行配置和验收结果。

## 3. 总体设计

保留现有物理、渲染、浏览器推理和离线训练管线，逐步补全运动控制及交互能力。

```text
对手与自身状态
    ↓
战术层：目标距离、移动方向、拳法、防守意图
    ↓
动作调度：准备 / 出拳 / 收拳 / 恢复，按有效连接点转换
    ↓
运动策略：拳击架势 + 步法 + 面向目标的全身动作
    ↓
PD 力矩 → MuJoCo 物理接触 → 状态反馈
    ↓
裁判与评估：有效命中、格挡、摔倒、动作质量
```

短期采用少量独立技能和经过验证的连接点。独立技能稳定后，评估训练共享的多技能控制器，降低策略切换的不连续性。是否统一网络，以过渡质量和部署性能为依据。

## 4. 具体修改方案

### 4.1 重做拳击架势与基础动作数据

涉及：`tools/cut_boxing_clips.py`、动作数据与清单、离线训练任务。

- 制作统一的前后脚拳击架势，通过机器人网格和碰撞几何检查拳套是否护头、肘部是否合理收拢。
- 第一批只保留守卫、前手刺拳、后撤及基本格挡；后续增加后手直拳、侧移、勾拳与连击。
- 每个动作包含准备、出拳、收拳和重心恢复，不仅截取拳头伸出的部分。
- 重定向后检查脚底接触、拳头轨迹、躯干旋转、关节范围、速度及执行器力矩限制。
- 重新设计片段过渡，缩短人工保持段；避免直接删除旧片段帧或加速播放后继续沿用旧策略。
- 对 jab、cross、hook 分别记录数据来源与策略来源，消除未标注的权重复用。

建议在动作元数据中增加：动作名称、左右手、动作阶段、支撑脚、有效出拳区间、允许衔接的阶段与后续动作。时间标注统一为秒，导出时按策略频率换算帧索引。

### 4.2 实现面向对手的进退与转向

涉及：`src/boxing_ai.mjs`、运动策略观测与指令接口、训练任务、策略导出元数据。

- 用双方相对位置计算目标朝向，加入平滑和转速限制，避免朝向指令突然跳变。
- 将目标距离、前后速度、横向速度和转向指令传入运动层。
- 增加可实际执行的前进、后退和绕行技能，替换追踪模式中所有步法映射到 `guard` 的行为。
- 按机器人臂展、目标部位及拳法标定有效距离，避免所有拳法共用狭窄的固定距离窗口。
- 训练成功前保留现有距离过远重置机制作为异常兜底；正常接战不应依靠重置。

第一版可以采用专门的拳击步法策略与出拳策略切换。切换需要匹配身体姿态、速度和支撑状态，不仅对关节角做插值。新增指令必须在训练中出现，不能直接传给不支持这些指令的旧网络。

### 4.3 增加目标感知与分阶段打靶训练

涉及：离线训练任务、`src/tracking_policy.mjs`、导出脚本与数值对齐测试。

按以下课程训练：

1. **固定靶**：稳定命中指定目标，出拳后回到守卫。
2. **随机位置靶**：覆盖合理的距离、高度和方向，避免只记住一个落点。
3. **移动靶**：随目标移动调整步法、朝向和出拳时机。
4. **固定套路对手**：对手按已知节奏出拳，学习格挡、后撤及反击。
5. **受限对练**：先限制拳法和速度，再逐步扩展到自由对练。

候选新增观测包括：目标相对位置与速度、对手拳套相对位置与速度、双方朝向差、自身动作阶段。训练和浏览器端必须使用一致的坐标系、顺序、归一化及时间采样方式。

简单旋转参考动作只可用于有限范围的朝向适配，不能替代目标条件策略，也不能保证碰撞后继续稳定。

### 4.4 按动作阶段调度与衔接

涉及：`src/boxing_ai.mjs`、动作元数据、`src/tracking_policy.mjs`。

将动作调度细化为：

```text
守卫 → 准备 → 出拳 → 收拳 → 恢复
```

- 为阶段定义允许的后续动作和连接条件，取代仅在整段结束时切换。
- 刺拳收拳后可衔接后手直拳；守卫或恢复阶段可转入后撤、侧移和格挡。
- 出拳发力阶段限制强行中断，防止不合理的关节目标突变。
- 过期的出拳意图需要取消或重新确认目标，避免排队后在不合适距离执行。
- 限定战术决策频率，复核当前追踪分支的决策触发逻辑，避免到达空闲阈值后每个物理步重新采样。
- 区分连续移动指令与离散出拳请求，防止新的步法请求覆盖有效拳法，也防止拳法请求长期阻塞移动。

短期只验收少量明确连接，例如“守卫→刺拳→守卫”和“刺拳→后撤”。复杂连击需要相应的训练覆盖，不将关节插值本身视为稳定性保证。

### 4.5 改进命中、格挡和受击响应

涉及：`src/boxing_ai.mjs`、碰撞几何及训练奖励。

- 综合接近速度、接触冲量、目标部位及有效出拳阶段判断命中。
- 以出拳事件为单位去重，避免持续贴身接触按冷却重复刷分。
- 区分轻触、格挡、有效命中；引入防守手臂与护头姿态时，同步检查碰撞体覆盖。
- 接触冲量需要依据物理步长计算与标定，避免直接使用未归一化的接触力跨配置比较。
- 物理碰撞已产生冲量，额外的展示击退应受限，并使用实际接触方向，避免重复放大。
- 把计分、展示效果与物理控制分开，使受击视觉效果不改变训练定义而不自知。

调整碰撞体的质量、惯量、摩擦或接触参数可能影响策略稳定性，必须保持训练与部署一致，并重新验证。

### 4.6 训练抗扰动恢复，逐步降低辅助

涉及：训练任务、场景配置、`src/boxing_ai.mjs` 和无头回归工具。

- 从轻微推力、随机初始姿态和轻接触开始，逐步加入出拳过程中的扰动及双人接触。
- 训练在脚底滑动、重心偏移和受击后恢复架势，必要时允许补步。
- 记录托力、扶正力矩、阻尼和分离力的使用量，避免辅助掩盖失败。
- 将辅助作为训练课程中的可递减变量，并单独评估无辅助版本。
- 检查 KO 时所有执行器是否正确进入预期状态；当前公共断力矩逻辑按 23 个执行器遍历，需要核对 29 自由度追踪场景的腕部执行器。

浏览器展示可暂时保留辅助开关，但验收报告必须说明是否开启以及具体参数。

### 4.7 基础能力稳定后再做战术自博弈

涉及：`src/tactics.mjs`、训练与评估脚本，以及新的对抗训练环境。

- 扩充观测，使战术层能识别对方进攻阶段、距离变化和自身恢复状态。
- 在新运动层上重新采集轨迹和训练，避免继续直接使用按旧 AMO 动作语义训练的策略。
- 使用历史对手池，并纳入固定套路和不同进攻风格，防止只适应一个对手。
- 奖励有效命中、防守成功、反击及合理距离；惩罚摔倒、异常动作和长期避战。
- 对推挤、持续贴身刷分、乱甩手、互相逃跑等行为设专门评估。
- 动作质量达不到目标时，再评估 AMP 等动作风格约束或技能隐空间方法。

在重新投入长时间训练前，复核策略更新的梯度符号、`netGain` 对梯度的影响及采样分布一致性；可用小规模数值梯度检查验证。不要用训练轮数替代算法正确性与效果验收。

## 5. 实施阶段与验收门槛

以下为建议的初始验收协议，具体命中与滑移阈值应在基线测量后冻结，不能观察结果后临时放宽。

| 阶段 | 交付内容 | 验收重点 |
|---|---|---|
| A：动作基线与单机技能 | 固定录像视角、动作指标、拳击守卫与刺拳 | 无辅助完成出拳和收拳，拳套护头、无明显滑脚，不靠辅助托举恢复 |
| B：距离与目标控制 | 进退、转向、固定与移动靶训练 | 从不同初始距离和朝向主动接近并命中，不依赖双方同时前倾或回合重置 |
| C：可解释攻防交换 | 固定套路对手、格挡/后撤、简单反击、阶段衔接 | 来拳触发防守，防守后能反击；无长时间无意义等待和频繁缠倒 |
| D：自由对练 | 多拳法、对手池、自博弈、风格约束评估 | 多个随机种子下长回合稳定，有距离变化、攻防切换和策略多样性 |

建议每个技能至少使用 20 个固定种子或固定扰动场景进行对比；自由对练至少统计 20 局、每局 60 秒。先记录基线，再确定目标通过率。人工验收使用同一视角、速度和录像时长。

建议持续记录：

- 无辅助摔倒率、数值发散次数、主动回合重置次数。
- 有效出拳次数、有效命中率、格挡成功率、受击后恢复时间。
- 攻击距离分布、追赶目标所需时间、近身缠斗持续时间。
- 脚底接触阶段的滑移量、躯干倾斜、动作切换时目标与力矩突变。
- 从战术意图到动作执行的延迟、守卫等待比例。
- 外部辅助力与力矩的使用量。
- 浏览器推理和物理耗时、帧率及仿真时间相对墙钟时间的推进速度。

## 7. 测试与部署约束

1. 新策略先验收单机动作，再验收目标控制和双机接触，最后进入自由对练。
2. 观测维度或顺序变化时，导出脚本、浏览器运行时和测试向量必须一起更新；旧权重不能按新接口加载。
3. 每个候选版本依次运行数值对齐、单机物理、双机物理及浏览器表现检查。
4. 无头与浏览器使用一致的辅助、场景和策略配置；辅助开关分别报告结果。
5. 正常回合稳定性与强制 KO/复位分开测试，避免主动重置遮蔽自然摔倒或计时问题。
6. 策略版本按 `.bin`、`_meta.json`、测试向量和动作清单整体保存、部署与回滚。
7. 训练课程、模型、控制频率、接触参数和随机种子写入验收记录。

现有回归命令保留为基础检查，后续按上述指标扩展：

```bash
node tools/test_amo.mjs 22
node tools/test_tracking.mjs vendor/policy/boxing_guard
node tools/test_tracking.mjs vendor/policy/boxing_jab
node tools/test_tracking.mjs vendor/policy/boxing_cross
node tools/test_tracking.mjs vendor/policy/boxing_hook
node tools/test_tracking_sim.mjs boxing_jab
node tools/test_tracking_boxing.mjs 22 boxing
```

## 8. 优先级与暂缓事项

最先落实三件事：

1. 拳击守卫与完整刺拳动作数据，并完成无辅助单机验收。
2. 面向目标的前进、后退和转向。
3. 从固定靶到移动靶的命中与收拳恢复训练。

在这些能力可靠前，暂缓大规模自由自博弈、复杂连击、更多拳法及重型策略架构。训练时间依据实际吞吐、收敛曲线和验收表现估算，不预先承诺固定迭代数即可达标。

## 9. 技术参考

- [BeyondMimic](https://beyondmimic.github.io/)：全身动作跟踪与可控制的运动生成，可参考其动作学习方法。项目已有相关追踪部署管线，优先复用。
- [AMP: Adversarial Motion Priors](https://xbpeng.github.io/projects/AMP/)：通过示范动作形成风格奖励，可作为“完成对抗目标时仍保持拳击动作形态”的后续研究方向。

以上研究提供方法参考，不是可直接替换进本项目的完整拳击方案；G1 的目标感知、接触稳定性和浏览器性能仍需实际训练与验证。
